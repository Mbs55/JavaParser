# XML Injection

## Overview

XML injection occurs when untrusted input is inserted into XML content, document structure, or attribute data without proper escaping. This can alter the meaning of XML documents and lead to downstream parser issues or XML-based attacks.

## CWE

CWE-91: XML Injection (aka Blind XPath Injection)

## Relevant Java APIs

- javax.xml.parsers.DocumentBuilderFactory
- org.w3c.dom.Document
- javax.xml.transform.Transformer
- javax.xml.parsers.DocumentBuilder

## Attack conditions

The application builds XML documents or payloads by concatenating untrusted values into tags, attributes, or text content.

## Vulnerable Java example

```java
String user = request.getParameter("user");
String xml = "<user><name>" + user + "</name></user>";
Document doc = builder.parse(new InputSource(new StringReader(xml)));
```

If user input contains malicious XML markup or closing tags, the document structure can change unexpectedly.

## Secure Java example

```java
Element user = doc.createElement("user");
Element name = doc.createElement("name");
name.appendChild(doc.createTextNode(userName));
user.appendChild(name);
```

## Detection indicators

- raw string concatenation into XML content or tags
- building XML from request values without DOM APIs or escaping
- unsafe templating for machine-readable configuration or SOAP payloads

## Mitigation

- build XML with DOM APIs and text nodes rather than concatenating strings
- escape unsafe characters before inserting values
- validate XML content and disable insecure parsing features
- review SOAP and XML-based APIs for signature and schema checks

## Common false positives

- safe XML generated by libraries or DOM APIs is not an injection issue
